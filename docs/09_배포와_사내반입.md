# 09. 배포와 사내 반입 — 무엇을 가져가고, 사내 PC 에서 무엇을 하나

> 2026-11-24 작성(M15 완료 시점, `trans` 브랜치 기준). 로드맵 **단계 12** 의 실행 안내다.
> 개발 PC(사외망)에서 더 할 수 있는 코드 일은 없다 — 남은 것은 전부 **사내 PC 에서만 확인되는 것**이다(§5).

## 0. 한 장 요약

| | 무엇 |
|---|---|
| 가져가는 것 | 저장소 ZIP 하나(코드·문서·시드). **데이터·비밀값은 들어 있지 않다** |
| 사내 PC 에 이미 있어야 하는 것 | 64비트 Python 3.12 · `uv` · 상위 폴더의 `secret\.env` · NAS 접근 권한 |

| 데이터가 쌓이는 곳 | `<MEETING_DATA_PATH 또는 NAS_BASE_PATH 또는 DATA_PATH>\meeting` — `meeting.db` · `photos\` · `exports\` |

## 1. 배포 패키지 구성

### A안 — 소스 ZIP (권장, 지금까지 쓰던 방식)

형제 앱 `dcost` 와 같다: 사내 PC 는 git 저장소가 아니라 **풀어 놓은 폴더**다(`D:\03.Data\meeting-main` 형태).
그래서 다음 판을 줄 때도 `git pull` 이 아니라 **ZIP 을 덮어쓴다**(§4).

ZIP 에 **들어가는 것** — 저장소 그대로:

```
app\            화면·라우터·서비스·템플릿·정적파일(글꼴 포함)
config\         전환 지점 — 망·비밀·프록시(settings.py) · 경로(paths.py)
modules\        전환 지점 — LLM 어댑터(llm_client.py) · NAS 접속(nas.py)
scripts\        seed_masters.py(기준정보 CSV → DB) · migrate_sections.py · fix_department_names.py
data\samples\   예시 메모·Mock 결과·기준정보 CSV(masters\)   ← 가상 데이터만
design\         토큰·시안(화면 작업용)
docs\           기획·데이터모델·로드맵·이 문서
schema\         LLM 출력 검증 스키마
tests\          pytest(12개 파일) — 사내 PC 에서도 돌려 본다
pyproject.toml · uv.lock            의존성(잠금본 그대로 설치한다)
setup_env.bat · run.bat             설치·실행 (ASCII + CRLF)
check_env.py · _smoke.py            가동 전 점검 · 회귀 확인
_netcheck.py · _freeport.py · _launcher.py · meeting.spec · build_exe.bat
.env.template                       필요한 키 **이름만** (값 없음)
CLAUDE.md · README.md · requirements.md · workinglog.md · 이어서_하기.md
```

ZIP 에 **들어가지 않는 것**(`.gitignore`) — 들어가면 안 되는 것들이다:

| 빠지는 것 | 왜 |
|---|---|
| `secret\.env` · 모든 `*.env` | 비밀값. 사내 PC 의 상위 폴더에 **따로** 둔다 |
| `*.db` · `data\photos\` · `data\exports\` | 운영 데이터·사진 원본. 덮어쓰면 현장 입력이 날아간다 |
| `.claude\shi.json` | PC 마다 다르다(`net`). 커밋하면 사내 판이 external 로 덮인다 |
| `.venv\` · `__pycache__\` · `build\` · `dist\` | 설치·빌드 산출물. 사내 PC 에서 새로 만든다 |

### B안 — 실행 파일 폴더 (파이썬·uv 를 못 깔 때)

```
cd /d D:\<meeting 폴더>
build_exe.bat          REM 개발 PC 에서 미리 만든다 → dist\meeting\ 폴더 전체를 가져간다
```

- 결과는 `dist\meeting\meeting.exe` + 딸린 파일들. **폴더째** 복사한다(exe 한 개만 떼면 안 된다).
- 실행하면 빈 포트를 찾아 `127.0.0.1` 에 서버를 띄우고 브라우저를 연다.
- 비밀값·데이터 규칙은 A안과 **같다** — exe 도 상위 폴더의 `secret\.env` 를 찾고 `<base>\meeting` 에 쓴다.
- PyInstaller 는 의존성이 아니라 **빌드할 때만** 당겨 쓴다(`uv run --with`) — `uv.lock` 은 그대로다.

### 패키지 밖에 있어야 하는 것 (사내 PC 쪽 준비물)

```
D:\03.Data\                 ← 예시. 아무 폴더나 되지만 아래 둘의 **상하 관계**는 지킨다
  secret\.env               ← 비밀값 하나. 여러 앱이 같이 쓴다(위로 올라가며 첫 파일을 찾는다)
  meeting-main\             ← ZIP 을 푼 폴더(= 이 저장소)
    .claude\shi.json        ← 이 PC 의 망 설정(net=internal). ZIP 에 없으니 직접 만든다
```

## 2. 사내 PC 에서 할 일 (순서대로)

> 운영 PC 앱은 대개 **D: 드라이브**에 있고 `cd` 는 드라이브를 바꾸지 않는다 — 첫 줄은 항상 `cd /d`.
> 폴더를 모르면 `dir /s /b D:\run.bat` 로 찾는다.

### ① 풀기

ZIP 을 `D:\03.Data\meeting-main` 에 푼다(이미 있으면 §4 의 「덮어쓰기」 규칙을 먼저 읽는다).

### ② `secret\.env` 채우기

`D:\03.Data\secret\.env` 에 **이름은 `.env.template` 그대로**, 값만 넣는다. meeting 이 보는 키:

| 키 | 넣는 값 | 없으면 |
|---|---|---|
| `NAS_BASE_PATH` | NAS 공유 경로 | 데이터가 로컬로 떨어진다 |
| `MEETING_DATA_PATH` | 데이터 폴더를 직접 지정할 때만 | 위 규칙대로 자동 |
| `MEETING_CENTRAL_PARQUET` | 중앙 parquet 폴더(비우면 NAS 하위) | 호선·마일스톤 동기화만 건너뛴다(앱은 뜬다) |
| `HTTP_PROXY` · `HTTPS_PROXY` | 사내 프록시 | **pypi 설치가 통째로 타임아웃난다** |
| `LLM_SOLAR_API_URL` · `LLM_SOLAR_API_KEY` · `LLM_SOLAR_MODEL` | 사내 LLM | AI 정리만 안 된다(§3) |
| `MEETING_LLM_CHAIN` | 외부를 막으려면 `sola` | 기본 `sola,openai` |
| `MEETING_EDIT_LOCK_MIN` | 편집 잠금 해제 분(기본 10) | 10분 |

- **값은 화면·로그에 찍지 않는다.** 점검 출력은 「설정됨 / 미설정」만 보여 준다.
- `.env` 를 다른 곳에 두려면 `SHI_ENV_FILE=경로\.env`.

### ③ 이 PC 를 사내망으로 선언

`D:\03.Data\meeting-main\.claude\shi.json` 에 한 줄:

```json
{ "net": "internal" }
```

망은 **이 값 하나로 정한다**(결정 ⑤ — 자동 감지 없음). 이것이 프록시·SSL·LLM 선택을 가른다.

### ④ 설치

```
cd /d D:\03.Data\meeting-main
setup_env.bat
```

- venv 는 **로컬 C:** (`%LOCALAPPDATA%\venvs\meeting`) 에 만든다 — 네트워크 드라이브 venv 는 numpy ImportError 를 낸다.
- 64비트 Python 3.12 를 강제하고, `uv sync --locked` 로 **잠금본 그대로** 설치한다.
- 망 판정은 `_netcheck.py`(SHI_NET → `shi.json` → 자동 감지)가 하고, 프록시 주소는 `secret\.env` 에서만 읽는다.
- 설치가 끝나면 `check_env.py` 를 돌리고 실행 여부를 묻는다.

### ⑤ 점검

```
cd /d D:\03.Data\meeting-main
%LOCALAPPDATA%\venvs\meeting\Scripts\python.exe check_env.py
```

Python 64비트 · 패키지 · `secret\.env` 위치 · 망 · 데이터 폴더 · DB · NAS 를 차례로 본다.
`[FAIL]` 이 있으면 그 줄의 안내대로 고친 뒤 다시 돌린다.

회귀 확인(선택이지만 권장):

```
cd /d D:\03.Data\meeting-main
%LOCALAPPDATA%\venvs\meeting\Scripts\python.exe _smoke.py
```

### ⑥ 실행

```
cd /d D:\03.Data\meeting-main
run.bat
```

빈 포트(8600~8610)를 찾아 `127.0.0.1` 에만 연다. 창을 닫거나 Ctrl+C 로 멈춘다.
**부서마다 자기 PC 에서 각자 실행한다** — 한 PC 를 서버로 쓰지 않는다(사내 정책).

### ⑦ 데이터 위치 정하기

| 쓰는 사람 | 권장 | 비고 |
|---|---|---|
| 한 PC 에서만 | 로컬 디스크(`MEETING_DATA_PATH=D:\meeting_data`) | 가장 빠르고 안전 |
| 여러 PC 가 같이 | NAS(`NAS_BASE_PATH` 하위 `meeting`) | 결정 ① 의 잠금 파일·DELETE 저널·매일 백업이 이 경우를 위한 것 |

- 옮길 때는 옛 폴더의 `meeting.db` · `photos\` · `exports\` 를 새 폴더로 **복사**하고 서버를 다시 켠다.
- `<base>\meeting` 은 git 밖이다 — **파일 백업 대상**이다(매일 백업은 `backups\` 에 쌓이고 기본 14개 유지).

### ⑧ 기준정보·호선 채우기

```
cd /d D:\03.Data\meeting-main
%LOCALAPPDATA%\venvs\meeting\Scripts\python.exe scripts\seed_masters.py
```

- `data\samples\masters\*.csv` 를 DB 에 넣는다(다시 돌려도 중복되지 않는다).
- **호선은 중앙 `pjtlist` 가 정본**이다 — 서버 시작·설정 화면 「지금 다시 읽기」·이 스크립트 끝에서 맞춘다.
- 부서 이름이 자리표시(「부서 1」…)로 보이면 `scripts\fix_department_names.py`.

### ⑨ 두 PC 동시 시험 (여기서 못 한 것)

1. 두 PC 에서 같은 NAS 데이터 폴더로 띄운다.
2. 같은 부서 회의자료를 양쪽에서 연다 → 나중에 연 쪽에 **「다른 곳에서 편집 중」** 띠가 떠야 한다(15-7).
3. 먼저 연 쪽에서 10분 동안 아무것도 하지 않는다 → 다른 쪽 「내가 편집」이 되어야 한다.
4. 양쪽에서 동시에 이슈 사실을 고쳐 본다 → 나중 저장이 **판 번호 409** 로 막혀야 한다(결정 ①).
5. 저장이 겹칠 때 「다른 PC 가 저장하는 중입니다」가 뜨는지(NAS 잠금 파일).

### ⑩ 부서 시범 (단계 13)

1~2개 부서로 한 주를 돌린다 — 메모 넣기 → 1차 초안 → 부서 자료 제출 → 공유회 → PPT.

## 3. LLM — 어느 PC 가 AI 를 쓰나

**코드에는 「지정 PC」 개념이 없다.** AI 를 쓰는 PC 는 **`secret\.env` 에 LLM 키가 들어 있는 PC** 다.

- 체인은 `MEETING_LLM_CHAIN`(기본 `sola,openai`). **키가 없는 공급자는 네트워크를 타지 않고 「미설정」으로 건너뛴다.**
- 그러므로 키를 **한 PC(예: 기획 PC)에만** 넣으면, 사실상 그 PC 에서만 AI 정리가 돌아간다. 나머지 PC 는 키가 없어 자동으로 꺼진다.
- 사내 LLM(SOLA)은 **사내망에서만** 닿고, 프록시를 우회해 직접 호출한다. 외부(OpenAI)는 프록시를 타야 한다.
  회사 메모를 외부로 보내지 않으려면 그 PC 의 `MEETING_LLM_CHAIN=sola` 로 둔다(원칙 9).
- **AI 가 없어도 전 기능이 돌아간다.** 키가 하나도 없으면 메모 자동 정리만 안 되고(실패 사유를 화면에 보여 준다),
  사람이 이슈를 직접 쓰면 그 뒤 흐름은 똑같다.
- 다만 **사내 LLM 서버가 PC·계정 단위로 접근을 통제하는지**는 우리 코드가 아니라 LLM 담당 쪽 정책이다 —
  키를 받을 때 「이 키를 어느 PC 에서 써도 되는지」를 같이 확인해야 한다.

## 4. 다음 판을 줄 때 (업데이트)

사내 폴더는 git 이 아니므로 **ZIP 을 덮어쓴다.**

```
cd /d D:\03.Data\meeting-main
REM 1) 앱을 멈춘다 (run.bat 창 Ctrl+C)
REM 2) 새 ZIP 을 이 폴더에 덮어쓴다
setup_env.bat          REM 의존성이 바뀌었을 수 있다. 안 바뀌었으면 금방 끝난다
```

- **덮어쓰면 안 되는 것**: `secret\.env`(상위 폴더라 애초에 안 겹친다) · `.claude\shi.json` · 데이터 폴더.
  ZIP 에는 이 셋이 없으므로 그냥 덮어써도 되지만, 혹시 폴더 안에 데이터를 두었다면 먼저 빼 둔다.
- DB 표·칸이 는 판이면 **처음 뜰 때 알아서 맞춘다**(없는 칸만 더한다 — 비파괴).
- 되돌리려면 옛 ZIP 을 다시 덮으면 된다. 데이터는 그대로다.

## 5. 여기(사외망 개발 PC)서 못 하는 것 = 사내 PC 에서만 확인되는 것

| # | 확인할 것 | 왜 여기서 못 하나 | 어떻게 확인 |
|---|---|---|---|
| 1 | **NAS 실제 연결** — 도메인 로그인 → 아이디·비번 3회, 못 붙으면 쓰기 차단 | NAS 가 사내망에만 있다 | 앱 첫 화면 → `/nas` 연결 화면. 일부러 틀린 비번 3회도 넣어 본다 |
| 2 | **중앙 parquet 실물** — `pjtlist`·`milestone` 열 이름·GT·날짜 우선순위(실적→전망→계획) | 사외망에 파일이 없다 | 설정 화면 「지금 다시 읽기」 → 호선 목록·D-day 가 맞는지 |
| 3 | **사내 LLM 실호출** — SOLA 응답·`<think>` 제거·스키마 검증 | 사내망에서만 닿는다 | 메모 넣기 한 건으로 블록이 나오는지. 실패 사유가 화면에 보이는지 |
| 4 | **두 PC 동시 사용** — 편집 잠금(15-7) · 판 번호 409 · NAS 잠금 파일 | PC 가 하나다(여기서는 브라우저 표 두 개로 흉내만 냈다) | §2 ⑨ |
| 5 | **프록시·SSL 설치** — `uv sync --locked` 가 사내 프록시로 받아지는지 | 사외망은 프록시가 없다 | `setup_env.bat` 이 끝까지 가는지 |
| 6 | **PPT 실물** — 맑은 고딕·자유 편집 좌표·사진 합성 | 글꼴·사진 원본이 사내에 있다 | 회의자료 PPT 를 내려받아 PowerPoint 에서 연다 |
| 7 | **운영 데이터 양** — 이슈 수백 건에서 화면·PPT 속도 | 여기 데이터는 시연용이다 | 이관 뒤 실제 주차로 한 번 |
| 8 | 메일함·DRM 엑셀 가져오기 | 결정 ③ 으로 **1차에서 꺼 두었다** | 2차에서 `MEETING_COM_IMPORTS=on` 으로 켤 때 |

## 6. 자주 나는 문제

| 증상 | 원인·해법 |
|---|---|
| `uv sync` 가 멈추거나 타임아웃 | 사내망인데 프록시가 꺼졌다. `secret\.env` 의 `HTTP_PROXY` 를 넣고 다시. 급하면 `set SHI_NET=corporate` |
| `SSL UnknownIssuer` | `setup_env.bat` 이 이미 `UV_SYSTEM_CERTS=true` 를 넣는다. 그래도 나면 `set SSL_CERT_FILE=C:\경로\corp-ca.pem` |
| `numpy ImportError` | venv 가 네트워크 드라이브에 있다. `%LOCALAPPDATA%\venvs\meeting` 으로 다시 만든다 |
| 32비트 Python 이 잡힘 | 64비트 3.12 를 설치한다. `win32` 휠이 아니라 **다운로드 실패**면 그건 망 문제다 |
| 앱은 뜨는데 호선이 비어 있음 | 중앙 parquet 폴더를 못 찾았다. `MEETING_CENTRAL_PARQUET` 또는 `NAS_BASE_PATH` 확인 |
| 「다른 곳에서 편집 중」이 안 풀림 | 그 PC 가 창을 닫지 않았다. 10분 뒤 자동으로 풀린다(`MEETING_EDIT_LOCK_MIN`) |
| 저장이 자꾸 409 | 두 사람이 같은 이슈를 고치고 있다. 화면을 새로 불러온 뒤 다시 고친다(내가 쓴 글은 복사해 두고) |

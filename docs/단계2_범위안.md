## 2. 만들 파일 4개 (정본) 과 공개 창구

### `config/paths.py` ← `path_config.py` 내용 이동
- 그대로 가져가는 공개 함수: `get_data_dir` `data_dir_choice` `db_path` `get_photo_dir` `get_import_dir` `get_export_dir` `get_backup_dir` `get_central_parquet_dir` `central_parquet` `is_network_path` `invalidate_cache`
- **바뀌는 것 하나**: 망 판정을 **`config.settings.net()` 하나로** 본다. `_nas_base()` 는 "NAS 경로가 있나" 확인만 하고, `net=internal` 일 때만 NAS 를 쓴다. 경로 존재로 망을 **추론하지 않는다**(결정 ⑤).
- `read_secret()` 은 `config/settings.py` 로 이사한다(비밀 읽기는 settings 책임). paths 는 `settings.secret("NAS_BASE_PATH")` 를 부른다.
- 경로 리터럴은 계속 이 파일 하나에만 둔다(공통지침 1).

### `config/settings.py` ← `app_config.py` 의 .env·프록시·LLM 키 부분
- 공개: `net()` · `secret(key)` · `proxies()` · `ssl_verify()` · `llm_keys()` · `env_label()`
- `net()` 은 `.claude/shi.json` 의 `net` 을 읽고, 환경변수 `SHI_NET` 으로 덮을 수 있게 한다(`setup_env.bat` 이 이미 쓰는 이름 — 단계 11 에서 이어진다). 자동 감지 없음.
- `.env` 는 **stdlib 로 직접 읽고 환경변수로 올리지 않는다**(`path_config.read_secret` 와 같은 정규식 방식, `SHI_ENV_FILE` → 상향 탐색). 이러면 "사외망에 사내 프록시가 주입되는" 사고가 구조적으로 불가능해진다. `load_dotenv` 는 부르지 않는다.
- `proxies()` 는 **`net=internal` 이고 값이 있을 때만** 프록시를 돌려준다. `ssl_verify()` = 프록시를 쓰지 않을 때 True.
- `app/settings.py` 는 **그대로 남긴다**(앱 업무 설정 = DB URL·LLM 체인·업무 값). `import app_config` 만 `from config import settings as cfg` 로 바꾼다.

### `modules/llm_client.py` ← `app/llm/client.py` 이동
- 체인 `sola,openai`(결정 ④) · Mock 은 테스트 전용 · 공급자별 실패 사유 누적 · `llm_call_log`(본문 미저장) 그대로.
- SOLA 금기 주석·코드 그대로 유지: `proxies={"http": None, "https": None}`(`None` 단독 금지) · `verify=False` · `max_tokens`·`stream` **미전송**.
- 키·프록시는 `config.settings` 에서 받는다. 프롬프트(`app/llm/prompts/*.md`)·스키마 위치는 그대로.

### `modules/nas.py` (신규 — 단계 2 는 뼈대까지)
- 공개: `ensure_connected() -> tuple[bool, str]` · `is_available()`
- `net=external` 이면 **아무것도 하지 않고 True**. `net=internal` 이면 도메인 로그인 먼저 → 실패 시 아이디·비번 입력 → `WNetAddConnection2`, **3회**까지, 비밀번호는 저장도 명령줄 전달도 하지 않는다. 실패하면 쓰기를 막는다.
- **실제 접속 구현·확인은 단계 5.** 단계 2 에서는 뼈대와 "쓰기 전 확인" 자리만 만든다(`services/nas_lock.py`·`db_guard.py` 에 끼우는 것도 단계 5).

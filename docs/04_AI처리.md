# 04. AI 처리 설계

모든 AI 호출은 `app/llm/client.py`의 어댑터를 거친다. 서비스 코드는 공급자를 모른다.

## 1. 어댑터와 폴백

```python
class LLMClient(Protocol):
    def complete_json(self, system: str, user: str, schema: dict, *, timeout: float) -> dict: ...
```

- 구현(`app/llm/client.py`): `sola`(사내, 프록시 우회·`max_tokens`/`stream` 미전송), `upstage`, `openai`, `mock`(샘플 파일). 형제 앱 costplan 의 검증된 호출 규칙을 옮겼다
- `secret/.env`의 `MEETING_LLM_CHAIN` 순서로 시도(기본 `sola,upstage,openai,mock` — 테스트 단계, CLAUDE.md 원칙 9 참고). 키는 공통 `LLM_SOLAR_*`·`LLM_UPSTAGE_*`·`LLM_OPENAI_*`. 키가 없으면 네트워크 없이 「미설정」으로 넘어가고, 접속 실패·4xx/5xx·JSON 아님·스키마 검증 실패 2회면 다음 공급자
- 응답은 항상 `schema/extraction.schema.json`으로 검증. 검증 실패한 출력은 화면에 쓰지 않는다
- 호출마다 `llm_call_log`(공급자, 모델, 소요 시간, 토큰, 성공 여부)를 남긴다. 본문은 남기지 않는다

사내 API 사양(엔드포인트, 인증, 이미지 입력 가능 여부, 사용량 한도)은 미확정. SOLA 는 OpenAI 호환 `/chat/completions` 로 가정해 `LLM_SOLAR_API_URL` 이 있을 때만 호출한다.

## 2. 작업 종류

| 작업 | 입력 | 출력 | 위치 |
|---|---|---|---|
| `extract_blocks` | 메모 원문(줄 번호 포함), 부서, 주차, 지난주 이어온 블록 요약 | 블록 목록 + 태그 + 근거 + 질문 | 작성 화면 ② |
| `match_carry_updates` | 이어온 블록 목록, 메모 | 블록별 업데이트 문장 + 근거 | 작성 화면 ③ — **M3 에서는 별도 호출 없이 `extract_blocks` 의 `carried_block_ref` 로 처리**(프롬프트에 이어온 블록 목록을 넣는다) |
| `extract_meeting_items` | 회의록 메모, 이번 주 블록 요약, 부서 목록 | 이슈 후보 / 기존 블록 연결 제안 (`schema/meeting_items.schema.json`, 근거 글자 그대로 검증, 연결은 목록에 있던 ID 만). 담당 부서는 AI 표기를 `services/departments.py` 가 다시 판정 — 줄임말(3부·해운·기술팀·실증랩) 연결, 한 부서로 좁혀질 때만, 못 좁히면 메모 줄의 「…부·팀·Lab」 낱말로 한 번 더 | 회의 화면 |
| `answer_knowledge` | 질문, 검색된 사례 상위 K개 | 요약 답변 + 인용 사례 ID | 지식창고 |
| `suggest_type` | 자유 글 블록 | 유형 제안 + 이유 한 줄 | 작성 화면 |

## 3. `extract_blocks` 처리 순서

1. **전처리**: 메모를 줄 단위로 나누고 `L1:`, `L2:` 번호를 붙인다. 사진 언급(`사진1`, `사진 2`)을 찾아 첨부 사진 ID 목록과 함께 넘긴다.
2. **별칭 후보 주입**: 메모에서 호선 번호(`25\d\d`, `SN25\d\d`, 옛 표기 `H25\d\d`)를 정규식으로 먼저 찾아 `ensure_sn` 으로 `SN2511` 형식으로 맞추고, 그 호선의 탑재 장비 별칭 목록만 프롬프트에 넣는다 (프롬프트 크기 제한).
3. **LLM 호출**: 프롬프트 `app/llm/prompts/extract_blocks.md`. 출력은 스키마 준수 JSON.
4. **후처리 (코드로 검증)**
   - 각 필드의 `evidence.line`이 실제 메모 줄 범위 안인지, `quote`가 그 줄에 실제로 들어 있는지 확인. 아니면 필드를 비우고 confidence 0
   - 태그 `raw_text` → `services/alias.py`로 기준정보 ID 확정. LLM이 준 ID는 믿지 않고 반드시 별칭 사전으로 다시 확인
   - confidence < 0.7 → 확인 필요(노란색)
   - 필수 누락(제목, 상태, 문제점의 원인) → 질문 생성. 섹션 전체 3개 초과 시 중요도 순으로 자름
5. **저장**: 블록, 태그, `source_span`, `ai_field_log(ai_value)` 저장. 사람이 이미 고친 블록이 있으면 그 필드는 건드리지 않는다.

## 4. 별칭 매핑 규칙 (`services/alias.py`)

순서대로 시도하고 처음 맞는 것을 쓴다.

0. 탑재 장비 ID 를 그대로 입력했으면 그 장비 (`EQ-SN2511-GE-02`)
1. 정규화: 공백·`#`·`.`·`/`·`-` 제거, 대문자화, 전각→반각, `No.2`→`2` (`D/G #2` → `DG2`, `G/E No.2` → `GE2`, `2번 발전기` → `발전기2`).
   입력 속 호선 번호(`2511`·`SN2511`·`S2511`·`H2511`)는 떼어 내 `ensure_sn` 으로 문맥 호선으로 쓴다(기준정보에 있는 호선만)
2. 문맥 호선이 있으면 `scope_hull_id = 그 호선` 별칭 우선
3. 전역 별칭 (`scope_hull_id is null`)
4. 패턴 규칙: `{장비약어}{번호}` → 그 호선의 `installed_equipment`에서 `system` 약어·`unit_no`로 찾기
5. 실패 → `raw_text`만 저장, 미연결

같은 단계에서 서로 다른 대상이 둘 이상 나오면 **고르지 않는다** — 미연결 + 후보 목록(`/api/alias/conflicts`).

사람이 검토 화면에서 고르면 `alias(source=user)` 추가. 같은 표기가 다른 대상으로 두 번 이상 매핑되면 충돌로 표시하고 기획부서 검토 대상에 올린다.

## 5. 프롬프트 원칙

- 시스템 프롬프트: 역할(조선소 시운전 주간보고 정리 보조), 출력은 JSON만, **메모에 없는 내용은 만들지 않는다**, 모르면 빈 값
- 본문은 작성자가 쓴 표현을 최대한 살린다. 문장 다듬기는 맞춤법·띄어쓰기 수준
- 숫자·단위·날짜는 메모 그대로 (예: `+38도` → `+38℃` 표기 정리는 허용, 값 변경 금지)
- 예시(few-shot)는 `data/samples/memo_W42_dept3.txt` ↔ `mock_extraction.json` 한 쌍

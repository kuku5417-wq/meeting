## 1. 목적

### 1-1. 풀려는 문제
- 커미셔닝팀은 매주 부서 회의 → 부서 현안 공유회 → 팀장 정보회의로 이어지는 회의자료를 **PPT 로 손으로** 만든다.
- 같은 이슈를 회의마다 다시 쓰고, 고친 내용은 그 PPT 에만 남는다. 그래서 다음 주·다음 호선에서 **이력과 지식이 끊긴다**.
- 비슷한 문제(같은 장비·같은 원인·자매선)가 반복돼도 지난 사례를 찾기 어렵다.

### 1-2. 하려는 것
| # | 목표 | 성공하면 |
|---|---|---|
| G1 | 이슈를 **한 번만 기록**하고 회의마다 골라 쓴다 | 회의자료 작성 시간이 줄고, 같은 이슈를 두 번 쓰지 않는다 |
| G2 | 회의를 거치며 고친 **사실이 이슈에 쌓인다** | 이슈 하나를 열면 처음부터 종결까지 경과·결정·근거가 다 있다 |
| G3 | 이슈를 **호선·장비·부위·증상·원인에 매핑**해 지식으로 남긴다 | 장비·자매선·원인으로 지난 사례를 바로 찾는다 |
| G4 | 회의 형식이 달라도(카드·한 줄·상세 한 장·표·외부 PPT) **같은 원장**에서 나온다 | 형식 때문에 기록이 갈라지지 않는다 |
| G5 | 시스템 밖에서 만든 자료도 **파싱해 원장에 잇는다** | 시스템이 못 그리는 자료도 지식에서 빠지지 않는다 |

### 1-3. 하지 않는 것 (1단계)
- 로그인·권한 관리(누가 했는지만 기록)
- 전자결재·메일 발송
- 모든 PPT 양식을 그대로 재현 (못 하는 것은 외부 자료로 붙인다)
- 일정 관리 시스템 대체 (호선 일정은 중앙 pjtlist·milestone 을 읽기만 한다)

## 2. 사람과 역할

| 역할 | 누구 | 책임 | 결과물 |
|---|---|---|---|
| **작성자** | 각 과 과장, 호선 담당자 | 이슈 최초 등록, 매핑, 이슈별 **1차 초안**, 진행 중 이슈 주간 업데이트, 종결 요청 | 이슈(원장), 1차 초안 |
| **부서 편집자** | 부장, 부서 스텝 | 우리 부서 초안을 골라 **부서 회의자료** 구성·수정·요약, 제출 | 부서 회의자료(제출본) |
| **팀 편집자** | 팀 스텝(기획) | 부서 제출본 **취합**(부서 현안 공유회), 이슈를 더 골라 **팀장 정보회의 자료** 구성(다른 형식), 종결 승인 | 공유회 자료, 팀장 정보회의 자료 |
| **회의 주관자** | 회의를 여는 사람 | 회의 진행, 코멘트·결정·종결 승인 기록 | 회의 기록(이슈 이력으로) |
| **누구나** | — | 외부 PPT·HTML 가져오기, 지식 검색 | 외부 자료 매핑 |

## 3. 업무 흐름

### 3-1. 한 주의 흐름 (정기)

| 언제 | 누가 | 하는 일 | 시스템 기능 | 남는 것 |
|---|---|---|---|---|
| 월~화 | 작성자 | 현장 메모 → 이슈 등록·매핑 / 진행 중 이슈 한 줄 업데이트 | F1 메모 AI 정리, F2 이슈 원장, F3 매핑, F4 주간 업데이트 | 이슈, 주차별 진행 |
| 화 | 작성자 | 회의에 올릴 이슈의 **1차 초안** 완성 → 「초안 완료」 | F5 1차 초안 | 초안(상세 한 장) |
| 수 | 부서 편집자 | 초안을 골라 부서 회의자료 구성, 표현 다듬기, 여러 이슈 요약, 사실 보완 → **제출** | F6 회의자료 구성, F7 요약 항목, F8 사실 되먹임, F9 제출 | 부서 회의자료, 이슈 갱신 |
| 목 | 팀 편집자 | 8개 부서 제출본 취합 → 부서 현안 공유회 자료 발행 | F10 취합, F11 발행·PPT | 공유회 자료(PPT) |
| 목 | 회의 주관자 | 공유회 진행 — 코멘트·결정·**종결 승인** | F12 회의 진행, F13 종결 | 결정·종결 이력, 사례 카드 |
| 금 | 팀 편집자 | 공유회 채택분 + 원장에서 추가 → **팀장 정보회의** 자료(한 줄 형식 등) | F6·F10·F11 | 팀장 정보회의 자료 |
| 수시 | 누구나 | 시스템 밖 PPT·HTML 가져오기 → 이슈에 연결 | F14 외부 자료 | 외부 자료 매핑, 이슈 갱신 |

- 매월 첫 주는 부서 현안 공유회 대신 **월간 현안**(상세 한 장 형식)을 연다.
- 호선별 회의·문제점·장비 리뷰는 필요할 때 연다. 같은 원장에서 조건만 바꿔 후보를 뽑는다.

### 3-2. 이슈 하나의 일생

```
메모(근거) ─▶ 이슈 등록(작성자) ─▶ 1차 초안 ─▶ 부서 회의자료에 채택(표현은 자료에, 사실은 이슈에)
   ─▶ 공유회 채택 ─▶ 팀장 정보회의(한 줄) ─▶ 주간 업데이트 반복 ─▶ 종결 요청 ─▶ 공유회에서 종결 승인
   ─▶ 사례 카드(지식창고) ─▶ 같은 장비·자매선 이슈가 생기면 「유사 사례」로 다시 나타남
```

이슈 상태: 진행 → (보류) → 종결 요청 → 종결
초안 상태: 작성 중 → 초안 완료 → 회의 반영됨

### 3-3. 고친 내용은 어디로 가나 (핵심 규칙)

| 구분 | 무엇 | 저장 위치 | 이력 |
|---|---|---|---|
| **사실** | 현상·원인·조치·일정·결정 필요·상태·사진·표·매핑 | **이슈**(원장) — 어느 회의자료에서 고쳐도 | 이전 값·새 값·누가·어느 회의·언제, 작성자에게 알림 |
| **표현** | 회의용 제목·한 줄·요약 문장·형태·순서·보여 줄 사진 | **그 회의자료에만** | 회의자료 판 |
| **회의 결과** | 코멘트·결정·종결 승인/보류 | 이슈 이력 | 어느 회의에서 |
| **외부 자료** | 사람이 「연결」을 고른 장의 사실 | 이슈(사실 규칙과 같음) | 근거 = 파일·쪽 위치 |

- 원본(메모·사진·외부 파일)은 바꾸지 않는다. 고친 것은 모두 새 판·이력으로 남는다.
- 요약 항목의 사실을 고치면 「연결 이슈 전부 / 고른 이슈만」 중에서 고른다.

## 4. 기능 목록

| ID | 기능 | 누가 | 입력 | 처리 | 출력 | 우선 |
|---|---|---|---|---|---|---|
| F1 | 메모 AI 정리 | 작성자 | 붙여넣은 메모·회의록·**사내 메신저 대화**(시간·보낸 사람 줄은 걷어내고 이름 미저장) | AI 가 이슈 후보로 나누고 유형·호선·장비·상태를 채움, 근거 줄 표시, **근거 없는 AI 문장 n 배지** | 이슈 후보(사람 확인 후 등록) | 필수 |
| F2 | 이슈 원장 | 누구나(작성자 중심) | 후보 또는 직접 입력 | 등록, 기존 이슈면 이번 주 진행으로 붙임. **데이터 그리드**(ID·유형·부서 / 호선+D-n / 장비 ← 현장 표기 / 제목+금주 진행 / 매핑 n/5 / 상태), 여유·조밀 밀도 전환. 담당은 **부서까지만**, 담당자가 아니어도 누구나 고칠 수 있음(이력·알림) | 이슈 ID(ISS/PRB/SHR-연도-번호) | 필수 |
| F3 | 지식 매핑 | 작성자 | 현장 표기(「2511 DG2」) | 별칭 사전으로 호선·장비·부위·증상·원인에 연결, 없으면 「미등록」 | 매핑 n/5, 미등록 표기 목록 | 필수 |
| F4 | 주간 업데이트 | 작성자 | 이슈별 한 줄 | 주차별 진행에 추가, 메모에 있으면 AI 가 채움 | 주차별 진행, 「업데이트 필요」 목록 | 필수 |
| F5 | 1차 초안 | 작성자 | 이슈 칸 | 칸에서 「상세 한 장」 자동 생성(현상·원인·조치·계획·결정 필요 + 사진), PPT 한 장으로 대신할 수 있음. 작업대 오른쪽 **실시간 16:9 미리보기에서 형태(상세 한 장·한 줄·비교표·간트) 바꿔 보기**, **자매선 선행 사례 경보** 한 줄 | 초안, 초안 상태 | 필수 |
| F6 | 회의자료 구성 | 부서·팀 편집자 | 후보 이슈 | 채택·순서·묶기(부서/호선/없음)·형태(한 줄·카드·사진 강조·표·상세 한 장·원본 슬라이드). **시작은 「지난주 이어받기」 또는 「빈 자료 + 추천 묶음」 중 선택(부서별 기억)**. 회의용 한 줄에 **자동 머리표 제안**(`[종결승인 대기]` `[결정필요·5주 미결]` `[공유]`). 한 회의 안에서 **①구성 ②진행 탭** 전환 | 회의자료 항목 목록 | 필수 |
| F7 | 요약 항목 | 부서·팀 편집자 | 여러 이슈 선택 | AI 가 공통점으로 요약 문장 제안 → 사람이 고침, 이슈 n개 연결 | 요약 항목 | 필수 |
| F8 | 사실 되먹임 | 편집자 | 회의자료에서 고친 사실 칸 | **이슈와 발행 전 자료에 바로 반영**, 이력(이전 값·새 값·누가·어느 회의)·작성자 알림. 작성자는 **바뀌기 전후 비교** 후 이의를 코멘트로. **발행본은 판 고정** — 「변경 n」만 표시하고 반영하면 2판 | 이슈 갱신, 「회의에서 고친 내용 n」 | 필수 |
| F9 | 부서 제출 | 부서 편집자 | 부서 회의자료 | 제출 기록(막지 않음, 미업데이트 n 경고), 다시 제출 가능. **마감 시각·남은 시간 표시**, 마감 1시간 전 미제출 강조 | 제출본, 제출 현황 | 필수 |
| F10 | 취합 | 팀 편집자 | 부서 제출본 8개 + 원장 | 제출본 항목을 참조로 가져옴(복사 아님), 원본이 바뀌면 알림. **마감 지난 부서는 「원장으로 채우기」**(열린 이슈·이번 주 업데이트로 자동, 「부서 미제출 · 원장 자동」 표시, 나중에 제출하면 교체). 발행 뒤 부서 수정은 「변경 n」 → 골라서 반영 | 공유회·팀장 정보회의 자료 | 필수 |
| F11 | 발행·PPT | 편집자 | 회의자료 | 미리보기 = PPT, 편집 가능한 .pptx 내보내기, 외부 원본 장 포함 | .pptx, 웹 자료 보기 | 필수 |
| F12 | 회의 진행 | 주관자 | 발행된 자료 | 진행자 화면 + 발표 화면, 코멘트·결정·회의 중 새 이슈 | 회의 기록 → 이슈 이력 | 필수 |
| F13 | 종결·사례화 | 공유회 주관자, 기획 | 종결 요청(조치 필수) | 승인/보류, 승인하면 사례 카드 생성 | 사례 카드(지식창고) | 필수 |
| F14 | 외부 자료 가져오기 | 누구나 | .pptx·.html (2단계 .pdf·.xlsx) | 장·문단 단위 추출 → 이슈 ID·호선·장비 표기로 연결 후보 → AI 유사도 → 사람이 연결/새 이슈/건너뛰기 | 이슈 갱신, 원본 슬라이드 첨부, 별칭 추가 | 필수 |

## 5. 결과물 정의

### 5-1. 이슈 (원장의 기본 단위)
| 항목 | 내용 |
|---|---|
| ID·유형 | ISS(이슈)·PRB(문제점)·SHR(공유정보), 연도·번호 |
| 기본 | 제목, 담당 부서, 작성자, 상태, 초안 상태, 중요 표시 |
| 내용(사실) | 현상, 원인, 조치·다음 할 일, 계획·일정, 결정 필요(무엇을·누구와) |
| 매핑 | 호선, 장비, 부위, 증상, 원인 코드 |
| 붙임 | 사진(이름·설명·순서·마커), 표, 계획 대비 실적, 진행률, 호선 비교, 원본 슬라이드 |
| 경과 | 주차별 진행 한 줄, 변경 이력(누가·어디서), 회의 결정, 근거(메모 줄·외부 자료 쪽) |

### 5-2. 회의자료
| 종류 | 만드는 사람 | 구성 | 형식(기본) | 결과 파일 |
|---|---|---|---|---|
| 부서 회의자료 | 부서 편집자 | 우리 부서 초안 채택·요약 | 카드·상세 한 장 | 제출본(웹), .pptx |
| 부서 현안 공유회 | 팀 편집자 | 8개 부서 제출본 취합 + 표지·요약 4칸·제출 현황 | 부서별 카드 | .pptx, 웹 자료 |
| 팀장 정보회의 | 팀 편집자 | 공유회 채택분 + 중요·장기 미결·이번 주 종결 + 원장 직접 | 한 줄 요약 + 핵심 지표 | .pptx, 웹 자료 |
| 월간 현안 | 팀 편집자 | 그 달 제출분·결정 필요·장기 미결·종결 | 상세 한 장 + 계획 대비 실적 | .pptx |
| 호선별 회의 | 팀 | 그 호선·자매선 열린 이슈 | 사진 강조 + 마일스톤 | .pptx |
| 문제점·장비 리뷰 | 팀 | 같은 장비 모델·원인 + 종결 사례 | 표 + 유사 사례 | .pptx |

### 5-4. 지식

|---|---|---|
| 사례 카드 | 종결된 이슈의 현상·원인·조치·사진 요약 | 지식창고, 유사 사례 |
| 장비 허브 | 장비별 진행·이력·동일 모델·자매선 선행·원인 순위·부위별 사진 | 작성·회의 중 참고 |

## 6. 규칙·제약

1. **막지 않는다** — 매핑 빈 곳·미업데이트·초안 미완료는 경고와 배지로만 보인다. 제출·발행·확정을 막지 않는다.
2. **원본 불변** — 메모·사진·외부 파일은 고치지 않고, 수정은 새 판으로 남긴다.
3. **근거 필수** — AI 가 채운 값과 외부 자료에서 온 값에는 근거(메모 줄·파일 쪽)가 붙는다.
4. **AI 는 제안, 사람이 확정** — 등록·연결·반영은 사람이 누른다.
5. **종결 승인**은 부서 현안 공유회(월간 현안 포함) 또는 기획 주관자만 한다.
6. **개인정보** — 자유 입력·파일명에 실명을 쓰지 않는다. 화면 표시는 마스킹한다.
7. **중앙 데이터는 읽기만** — 호선·마일스톤은 pjtlist·milestone 이 정본이다.

## 9. 확인이 필요한 것

1. ~~사실 칸 수정 반영 방식~~ → 바로 반영 + 알림(10-22).

## 1. 왜 다시 설계하나

사용자 피드백(2026-10-21)
- 지금 너무 불편하다.
- 이슈 등록은 **지식으로 쌓기 위한 매핑 과정**이다.
- 회의자료는 더 다양한 형태로 바뀔 수 있어야 한다.
- 회의가 많아지면 이슈 중에서 **골라 채택**하는 방향이어야 한다.

지금 구조(M0~M8)가 불편한 근본 원인:

| # | 문제 | 지금 구조 | 결과 |
|---|---|---|---|
| 1 | 기록 = 보고서 | 「주차 × 부서 섹션」에 블록을 넣으면 그게 곧 보고서다(`section`·`section_block`) | 고르기·빼기·다른 회의에 다시 쓰기가 안 되고, 회의 종류가 주간 하나로 고정 |
| 2 | 지식 품질 검사가 확정을 막음 | 장비 연결·태그 확인·마커 부위가 「확정 전 체크」 | 회의 준비와 지식 정리가 한 줄에 엉킴 |
| 3 | 유형 = 출력 위치 | 대시보드는 지표 쪽, 나머지는 현황 쪽에만 | 같은 이슈를 회의마다 다른 모양으로 못 보여 줌(지표 없는 대시보드는 아예 빠짐) |
| 4 | 화면 한 장에 모든 일 | 작성 화면에 메모·이슈·사진·지표·체크·미리보기·내보내기 | 무엇을 하는 화면인지 흐림 |

## 2. 3층 구조

```
① 기록·매핑 (이슈 원장)          ② 회의                    ③ 회의자료 구성
   메모 → 이슈 카드                 종류·주관·날짜·대상 조건      후보에서 채택 → 묶기 → 순서
   호선·장비·원인·사진·표 매핑        (템플릿이 미리 채움)          → 항목별 형태 → 미리보기 = PPT
   상태·주차별 진행·이력                                           → 발행 → 회의 진행(코멘트·결정)
        │                                ▲                                │
        └──────── 원장의 이슈가 후보가 됨 ──┘        회의 코멘트·결정 → 이슈 이력 ◀┘
```

| 층 | 누가 | 하는 일 | 막는 것 |
|---|---|---|---|
| ① 이슈 원장 | 부서 작성자 | 이슈를 기록하고 지식으로 매핑한다. 이슈는 주차·회의에 묶이지 않는다. 진행 중 이슈는 매주 한 줄 업데이트, 끝나면 부서가 **이번 주 제출** | 없음 — 매핑 완성도는 배지(「매핑 3/5」), 제출은 경고(「미업데이트 2」)만 |
| ② 회의 | 회의 주관자(팀 또는 부서) | 회의를 만든다. 종류를 고르면 템플릿이 조건·묶기·형태를 채운다 | — |
| ③ 회의자료 | 회의 주관자 | 후보 이슈를 채택해 회의자료를 구성하고 발행한다 | 채택한 이슈의 매핑 빈 곳은 경고만 한다 |

- 주간 정기 회의는 2종이다(실제 운영). **부서 현안 공유회** — 부서장들이 모여 각 부서 이슈를 공유한다. **팀장 정보회의** — 팀장이 본부장에게 팀 이슈를 보고한다.
- 흐름: 부서가 원장 정리 → **제출** → 부서 현안 공유회(후보 「부서 제출」 묶음에서 채택, 종결 승인) → 팀장 정보회의로 올릴 것을 고름.
- 부서는 **부서 회의자료**를 만들어 제출한다(§2-1). 공유회 자료는 그 취합이다.
- 같은 이슈가 여러 회의에 채택될 수 있다. 예: 부서 현안 공유회와 SN2511 호선별 회의.
- 회의에서 남긴 코멘트·결정·종결 승인은 그 **이슈의 이력**에 쌓인다. 그래서 지식이 회의를 거칠수록 풍부해진다.

### 2-1. 역할과 자료 흐름 (2026-10-21 확정 — 앞의 「부서는 제출만」 가정을 대신함)

```
① 이슈 원장 + 1차 초안        과장 · 호선 담당자
   이슈 등록 → 칸을 채우면 「상세 한 장」 초안이 자동으로 그려짐 (PPT 한 장을 초안으로 올려도 됨)
        │ 고르기
② 부서 회의자료               부장 · 부서 스텝
   초안을 골라 회의에 맞게 고침 · 여러 이슈를 한 장으로 요약
   고친 「사실」 ──▶ 이슈 · 지식에 바로 반영(+작성자 알림)
        │ 제출
③ 부서 현안 공유회 자료        팀 스텝(기획) — 부서 제출본 취합 + 표지·요약·부서 순서
        │ 고르기 + 원장에서 직접 추가
④ 팀장 정보회의 자료           팀 스텝(기획) — 같은 이슈를 다른 형식으로(한 줄 요약 등)

◇ 외부 자료 가져오기(누구나): PPT · HTML → 장마다 AI 추출 → 기존 이슈 연결 / 새 이슈 / 건너뛰기 → 지식 업데이트. 원본 장은 회의자료에 그대로
```

| 역할 | 하는 일 | 화면 |
|---|---|---|
| 과장 · 호선 담당자 | 이슈 등록·매핑, 1차 초안(자동 + 손봄, 또는 PPT 한 장), 주간 한 줄 | 홈 · 이슈 · 가져오기 |
| 부장 · 부서 스텝 | 초안 골라 부서 회의자료 구성·수정·요약, 제출 | 회의자료 구성(부서) · 가져오기 |
| 팀 스텝(기획) | 부서 자료 취합(공유회), 팀장 정보회의 구성, 종결 승인(주관자) | 회의자료 구성(팀) · 가져오기 |

**고친 내용의 반영 규칙**
- **사실** — 현상 · 원인 · 조치 · 일정(계획 대비 실적) · 결정 · 사진·표: 어느 회의자료에서 고쳐도 **이슈에 바로 반영**. `ai_field_log` 처럼 (이전 값, 새 값, 누가, 어느 회의)를 남기고 작성자에게 알림. 지식창고·사례 카드도 이 값을 쓴다.
- **표현** — 회의용 한 줄, 요약 문장, 강조, 순서, 형태: **그 회의자료에만** 남는다.
- **요약 항목** — 한 항목이 이슈 여러 개를 가리킬 수 있다(`report_item_block`). 요약 문장은 표현이라 회의에만, 각 이슈의 사실은 각 이슈로.
- **발행본** — 사실 반영은 이슈와 **발행 전** 회의자료까지. 발행한 자료는 판으로 고정하고 「변경 n」만 표시, 반영하면 2판(2026-10-23, `docs/08`).
- **외부 자료** — 원본 파일은 바꾸지 않고 보관(원칙 1). 장에서 뽑은 사실은 사람이 「연결」을 고른 것만 이슈에 반영(원칙 3: 근거 = 그 장의 위치).

> **최종 시안(2026-10-23)**: `design/mockups/README.md` 「★ 최종 시안」 — B안 화면 + 회의자료 스튜디오(`v2b-studio.html`). 아래 §4 화면 표의 시안 파일명은 A안 기준이다.

## 3. 회의 종류와 템플릿

| 종류 | 주관 | 생성 | 후보 조건(기본) | 자동 채택 | 묶기 | 기본 형태 | 표지·요약 | 종결 승인 |
|---|---|---|---|---|---|---|---|---|
| 부서 현안 공유회 | 팀(기획) | 매주 자동 | 이번 주 부서 제출분 + 열린 이슈·문제점 + 이번 주 공유정보 | 종결 요청 | 부서별 | 카드(사진 있으면 사진 강조) | 요약 4칸 + 부서 제출 현황 | **가능** |
| 팀장 정보회의 | 팀(기획 구성·팀장 확인 — 가정) | 매주 자동 | 공유회 채택분 · 중요 표시 · 장기 미결 · 이번 주 종결 | 중요 표시 | 없음 | 한 줄 요약 | 핵심 지표 4개 + 이번 주 종결 n | 불가 |
| 월간 현안 | 팀(기획) | **매월 첫 주, 그 주 부서 현안 공유회 대신** | 그 달 부서 제출분 · 결정 필요 · 장기 미결 · 그 달 종결 | 결정 필요 · 종결 요청 | 부서별 | 상세 한 장 | 월간 요약 + 계획 대비 실적 | **가능** |
| 호선별 회의 | 팀 | 필요할 때 | 그 호선 + 자매선의 열린 이슈 | 선주·선급 관련 | 장비·원인별 | 사진 강조 | 호선 요약(진행률·미결) | 불가 |
| 문제점·장비 리뷰 | 팀 | 필요할 때 | 같은 장비 모델·원인의 이슈 + 종결 사례 | 반복 발생(3건 이상) | 장비·원인별 | 표 + 유사 사례 | 원인별 건수 그래프 | 불가 |

- **종결**은 이슈에 쓰는 말이다. 부서가 「종결 요청」(조치 내용 필수) → **부서 현안 공유회**의 회의 진행 화면에서 승인/보류, 또는 **기획 주관자**가 언제든(홈 「종결 요청」) 승인. 승인하면 사례 카드.
- 회의자료는 부서가 **제출**한다.

템플릿은 시작값일 뿐이고, 회의마다 바꿀 수 있다.

### 3-1. 표시 형태와 이슈에 붙이는 것 (2026-10-21, 지금 PPT 양식 8장 분석)

지금 부서 PPT 는 「이슈 1건 = 1장」이 가장 많고, 계획 대비 실적 간트·호선 비교표·구역별 진행률·자유 구성 전략 장이 섞여 있다.

| 표시 형태 | 슬라이드 | 쓰는 곳 |
|---|---|---|
| 한 줄 | 제목 + 회의용 한 줄 | 팀장 정보회의 |
| 카드 | 내용·담당·상태 (+작은 사진) | 공유회 기본 |
| 사진 강조 | 사진 크게 + 요약 | 행사·현장 |
| 표 | 같은 묶음을 표 한 장으로 | 리뷰 |
| **상세 한 장** (새) | **현상 / 원인 / 조치·계획 / 결정 필요** 4칸 + 사진·도면 + 붙인 표·차트 | 월간 현안, 큰 문제점 |
| **원본 슬라이드** (새) | 부서가 만든 PPT 장 그대로 | 틀에 안 맞는 전략·분석 장 |

- 「상세 한 장」의 칸은 이슈 필드와 지식 매핑에서 그대로 온다(증상 → 현상, 원인, 조치·다음 할 일 → 조치·계획). 따로 쓰지 않는다.
- **결정 필요**: 이슈에 「결정 필요」 칸(무엇을, 누구와 — 예: 선주 협의, 보증기간 연장 요구)을 둔다. 회의 진행 화면에서 따로 모아 보이고, 결정을 남기면 이슈 이력에 쌓이고 칸이 비워진다.

이슈에 붙이는 것(사진·표 외에)
| 붙이기 | 입력 | 슬라이드 |
|---|---|---|
| 계획 대비 실적 | 항목마다 계획 시작·종료 / 실적 시작·종료 | 간트(계획 회색·실적 파랑) + 시작·종료·시간·차이 표 자동 |
| 진행률 | 구역·항목마다 단계 목록 + 진행률 % | 구역별 막대 + % |
| 호선 비교 | 같은 문제의 다른 호선 이슈를 연결(자매선·같은 장비 모델 추천) | 호선을 열로 하는 비교표(발생 시점·위치·성상·조치) |
| 원본 슬라이드 | .pptx 에서 장 고르기 또는 이미지 | 그대로 한 장 — 원본은 바꾸지 않는다(원칙 1) |

- 원본 슬라이드만 붙인 이슈도 제목·호선·장비는 매핑한다(검색·지식창고용). 매핑 배지로 빈 곳을 보인다.

### 3-2. 색 · 글꼴 · 글자 크기 (2026-10-22 검토·확정)

- **회의자료(PPT·발표 화면·회의자료 보기) = A안 네이비**: 띠 `--slide-band` #26344A · 구역 막대 `--slide-sec` #3B5A7A · 「주간 현안」 태그 `--slide-tag` #F0A63C + 남색 글자(대비 7.6:1 — 지금 PPT 의 흰 글자는 2.4:1). **앱 주 색도 네이비**(2026-10-22 사용자 결정) — `--accent` #2C4566. 공유정보 색은 주 색과 겹치지 않게 청록 #0B6E78 로 바꿈. 슬라이드는 다크 화면에서도 흰 바탕. `pptx_builder.py` 색표 같은 값.
- **글꼴**: 본문 글꼴 하나(IBM Plex Sans KR = 로컬 Meeting Sans KR), 제목 굵기 600. Gothic A1 제외. PPT 는 맑은 고딕.
- **글자 크기**: 5단계 12 · 14(본문) · 16 · 20 · 26, 화면 최소 12px(슬라이드 미리보기 안쪽만 예외).
- **색 의미 정리**: `--ok` 진하게(4.44 → 5.29:1) · 「결정 필요」 전용 `--decide` 신설(보라를 시안 설명색과 분리) · 회의 종류 배지는 의미 색 없이 테두리(`.pill.kind`) · 「종결 요청」 숫자는 대기 중이라 `--accent` · 매핑 배지는 어디서나 「n/5」 숫자 같이.

| 화면 | 시안 | 핵심 동작 |
|---|---|---|

- 배치 결정(2026-10-21)
  - A: 메모 입력창은 원장 위 「+ 메모로 만들기」 버튼으로 접는다(누르면 가운데 칸이 메모 입력·AI 후보 확인으로 바뀜). 원장에 「업데이트 필요 n」 탭과 행마다 한 줄 입력. 저장·종결 요청·부서 이관 줄은 화면 바닥에 고정.
  - B: 회의 카드 → 회의자료 보기(읽기) → 「수정」 → 구성(편집). 보는 사람이 대부분이라 읽기를 먼저 둔다. 「회의 만들기」는 버튼 + 오른쪽 서랍. 부서 현안 공유회·팀장 정보회의는 정기 회의로 매주 자동 생성.
  - C: 부서 현안 공유회는 머리줄 아래 8개 부서 제출 현황 띠. ▲▼ 대신 끌어서 옮기기(키보드 ▲▼ 유지), 여러 항목 한꺼번에 형태 바꾸기, 미리보기 「크게 보기」.
- 「확정 전 체크」는 없어진다.
  - 지식 품질은 이슈 카드의 매핑 배지와 「매핑 빈 곳」 필터로 본다.
  - 회의자료 품질은 구성 화면의 경고로 본다.
- 발행은 막지 않는다.

이전(마이그레이션)
- 주차별 부서 섹션 하나 = 그 주 부서 회의 하나. 섹션의 블록 = 채택 항목(카드). 확정 섹션 = 발행.
- 주차별 팀 보고서 = 주간 팀 회의 하나. 각 부서 회의의 채택분을 그대로 채택한다.
- 원본 메모·사진·이력은 그대로 둔다(원칙 1).

## 6. 결정한 것 (2026-10-21)

1. 「회의용 한 줄」은 **회의마다 따로** 둔다. 기본값은 그 이슈의 이번 주 진행 한 줄.
2. 종결 승인은 **부서 현안 공유회에서만, 또는 기획 주관자가** 한다(CLAUDE.md 원칙 7 수정).
3. 부서 제출분은 부서 현안 공유회 후보의 **「부서 제출」 묶음**으로만 보인다. 자동 채택하지 않는다(종결 요청은 자동 채택).
4. 지표는 이슈 원장에서 빼고 **별도 「지표」 화면**에서 입력한다. 회의자료에는 골라서 요약 항목으로 넣는다.
5. 지금 작성 화면은 **이전이 끝날 때까지 읽기 전용**으로 두고 M12 에서 없앤다.
6. 월간 현안 회의는 매월 첫 주 부서 현안 공유회 대신 연다(정기 회의 규칙).
7. 「상세 한 장」·「원본 슬라이드」 형태, 「결정 필요」, 계획 대비 실적·진행률·호선 비교 붙이기, 지표 「기간 표」를 넣는다(§3-1).
8. 진행 중 이슈의 주간 업데이트는 **원장에서 한 줄 입력**(메모에 있으면 AI 가 채움). 부서 「이번 주 제출」은 **막지 않고 경고만**.

9. 역할·흐름은 §2-1 — 부서 회의자료 층을 둔다(앞의 「부서는 제출만」 가정 폐기). 1차 초안은 이슈 칸에서 자동(+PPT 한 장 허용), 사실 수정은 이슈에 바로 반영 + 작성자 알림, 외부 자료 가져오기는 모든 역할.

확인이 필요한 가정: 팀장 정보회의 자료는 기획이 구성하고 팀장이 확인한다.

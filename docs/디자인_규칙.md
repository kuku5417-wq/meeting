## 2. 토큰 구조 (tokens.css 3층)
| 층 | 이름 | 누가 쓰나 |
|---|---|---|
| 원시 색 | `--gray-*` `--blue-*` `--red-*` `--navy-700` `--cat-1~5`(+`-soft` `-ink`) | tokens.css 안에서만. 화면 코드는 쓰지 않는다(분류 칩만 `--cat-*` 직접) |
| 의미 색 | `--bg` `--surface` `--surface-2` `--fill` `--fg` `--muted` `--line` `--field-line` `--accent*` `--focus` `--danger*` `--side-*` `--slide-*` | **화면 코드는 이 이름만** |

| 고정 | `--canvas*` `--mini*` `--toast-*` `--present-bg` | 테마와 관계없음 — 편집 캔버스(어둡게)·알림·발표 화면 |

## 3. 색 규칙
1. **색은 토큰 변수로만.** hex·rgb를 CSS·템플릿·JS에 직접 쓰지 않는다(예외: tokens.css, 사진 마킹 색은 데이터).
2. **상태·동작 색은 세 가지.**
   - 회색 단계 — 바탕·카드·선·글자, 유형 라벨(이슈·공유)·완료·종결 요청
   - 파랑 `--accent` — 주 동작 버튼, 선택·지금 위치, **확인할 것**(근거 표시·발행 뒤 바뀜·사실 칸)
   - 빨강 `--danger` — 문제점, 빈 필수 칸, 일정 임박·기한 지남, 넘침, 미제출
3. **나머지 구분은 색 대신 글자·아이콘·굵기.** 유형 라벨은 테두리 글자(문제점만 빨강), 완료는 체크 아이콘, 결정 필요는 굵은 글자.
4. **분류 색(`--cat-1~5`)은 선종·유종·장비 계통에만.** 값마다 색 고정(예: LNG선 = 1), 6번째부터 회색 「기타」, 상태·부서·개별 장비에는 쓰지 않는다. **칠 색만으로 표시하지 않는다**(흰 바탕 대비 2.5~2.8) — 칩(`-soft` 바탕 + `-ink` 글자, 대비 7 이상) 또는 글자와 함께.
5. 한 화면에 쓰는 색 = 회색 + 파랑 + 빨강 + (분류 칩). 그 밖의 색이 보이면 ux-reviewer [필수].
6. 글자 대비 4.5:1 이상, 입력칸 테두리 3:1 이상 — 토큰끼리 조합하면 지켜진다(값은 tokens.css 머리말).
7. 다크 모드는 같은 이름, 다른 값. 주 색은 다크에서도 파랑.

## 4. 그 밖의 규칙
1. 이모지를 쓰지 않는다. 상태 기호는 아이콘 + 글자.
2. 한 화면에 주 버튼(파랑 채움)은 하나.
3. 확인창 대신 바로 실행 + 「되돌리기」. 되돌릴 수 없는 것(발행·삭제 확정)만 확인.
4. 빈·불러오는 중·오류·완료 상태를 모두 둔다. 비활성 버튼에는 이유.
5. 폭 400px에서 깨지지 않게(휴대폰 화면을 따로 만들지는 않음). 누르는 영역 PC 32px·휴대폰 44px 이상.
6. 글자 크기는 `--fs-1~5`만.

## 5. 컴포넌트 방식 (같은 일 = 같은 방식, v2m·B안 원칙)
| 하는 일 | 방식 | 시안 근거 |
|---|---|---|
| 다음 일로 | 끝내면 다음 칸으로(「기록하고 다음」 「초안 완료 → 다음 초안」, Enter) | v2m 홈·이슈·진행 |
| 저장 | 자동 저장, 저장 버튼 없음(「저장됨」 표시는 실제 저장 뒤에만) | v2m 이슈 |
| 삭제·빼기 | 바로 실행 + 되돌리기 알림 | B안 |
| 목록 | 흰 카드 그룹 목록, 선택 행 = 연한 파랑 + 왼쪽 파란 막대 | v2m |
| 걸러 보기 | 칩 + 찾기 칸 | v2m 이슈 원장 |
| 여러 건 처리 | 체크한 뒤 일괄 동작(골랐을 때만 일괄 바) | v2m 이슈 원장 |
| 순서 | 끌어서 옮기기 + 키보드 ↑↓ | 스튜디오 |
| 바뀐 것 | 연한 파랑 「변경」 표시 | v3 (예전 주황) |
| 근거 | 연한 파랑 바탕 | v3 (예전 노랑) |
| 사실 칸(이슈를 바꾸는 곳) | 연한 파랑 칸 + 「여기서 고치면 이슈에 반영 · 작성자 알림」 | v3-studio, 결정 ⑦ |
| 분류 | 칩(`.cat`) | v3-tokens |
